# Einstein 产品梳理与系统设计（基于 LangChain）

> 版本 v0.1 · 2026-11-05 · 仅产品设计，不含实现代码

---

## 1. 产品定位

一句话：**企业/个人可私有化部署的 AI 能力平台**——以知识库 RAG 为底座，以智能体为运行时，以技能/专家为可复用的能力组织单元，以 MCP 为外部世界（工具、数据、系统）的统一接入协议。

目标用户分三层：

| 层 | 用户 | 关心什么 | 对应功能 |
|---|---|---|---|
| 消费层 | 普通使用者 | 问答准不准、快不快 | 智能问答、专家对话 |
| 创作层 | 运营/管理员 | 搭知识库、配专家、装技能 | RAG 管理、专家/技能管理 |
| 集成层 | 开发者/IT | 接外部系统、管权限、看监控 | MCP、API、审计、观测 |

---

## 2. 核心概念模型（产品设计的灵魂）

六个功能不是平级的，是一条**自底向上的能力组装链**：

```
工具(Tool / MCP)          ← 最小能力原子：一个可调用的函数
   ↓ 组合
技能(Skill)               ← 可复用能力包：提示词 + 工具组合 + 参数
   ↓ 组合
专家(Expert)              ← 面向用户的角色：人设 + 技能组合 + 知识库绑定 + 模型偏好
   ↓ 实例化
智能体(Agent)             ← 运行时执行体：LangGraph 编排，绑定专家/技能运行
   ↓ 面向用户
应用/智能问答(App)        ← 终端入口：选专家/Agent + 挂知识库 → 对话
```

关键产品判断：

1. **专家 ≠ 智能体**。专家是"配置态"（他是谁、会什么、读哪些资料），智能体是"运行态"（一次任务执行的编排实例）。一个专家可被多个应用引用。
2. **技能是中间复用层**。没有技能层，"给销售专家加个查 CRM 能力"就要改专家配置；有了技能层，装个技能包即可。技能应支持导入/导出/分享（技能包格式：manifest + 提示词 + 工具声明 + 示例）。
3. **MCP 不是功能，是协议**。MCP Server 是工具的一种来源，与"内置工具"平级，统一进 **Tool Registry**，上层（技能/智能体）不感知工具来自哪里。
4. **知识库是被引用的资源**，不是对话的附属品。同一知识库可被多个专家/应用挂载，检索权限跟随知识库 ACL。

## 3. 功能模块梳理

### 3.1 知识库 RAG 管理

**摄取管道（写路径）**：
上传（多格式：PDF/Word/Excel/Markdown/HTML/网页 URL）→ 解析（含 OCR/表格识别）→ 清洗 → 切片（策略可配：固定长度/递归/语义/父子切片）→ 嵌入（批处理）→ 写入向量库 + 全文索引（BM25）。

**检索管道（读路径）**：
查询改写（多轮指代消解）→ 混合检索（向量 + BM25 + 可选知识图谱）→ 重排（Reranker，本地 Qwen3-Reranker 或 API）→ 压缩组装（top-k、上下文窗口控制）→ **引用溯源**（回答带出处，点击可定位原文段落）。

**管理能力**：知识库 CRUD、文档版本与增量更新（按 hash 去重）、切片预览与人工修正、检索测试台（输入 query 看召回效果，调参）、知识库 ACL（谁可用）、摄取任务队列与失败重试。

### 3.2 智能问答

会话管理（多会话、历史持久化、重命名/搜索）、多轮上下文、流式输出（SSE）、模式切换（直接问答 / 知识库问答 / 联网问答）、引用展示、反馈（点赞点踩→反哺评测集）、多模型切换、消息重新生成与分支。

### 3.3 智能体

- 编排引擎用 **LangGraph**（状态机/图编排，支持循环、人工介入、中断恢复），不用裸 AgentExecutor。
- 预设模式：ReAct（工具循环）、Plan-and-Execute（复杂任务拆解）、固定 Workflow（确定性流程）。
- 记忆体系：短期（会话窗口内）+ 长期（跨会话，向量存储用户偏好/事实）。
- 运行过程可视化：思维/工具调用步骤流式展示给用户。
- 运行控制：超时、步数上限、费用/Token 预算、人工确认敏感操作。

### 3.4 技能管理

技能包 CRUD、版本管理、启用范围（个人/工作区/全局）、导入导出（zip 包：manifest.json + 提示词 + 工具声明 + few-shot 示例）、技能市场（后期）、调试沙箱（试运行技能，看工具调用轨迹）。

### 3.5 专家管理

专家 CRUD、人设提示词编辑（结构化：角色/语气/边界/输出格式）、技能勾选、知识库挂载、模型与参数偏好（温度/上下文长度）、开场白与推荐问题、发布（草稿→测试→上线）、头像与展示配置。

### 3.6 MCP 接入

MCP Server 注册（stdio / SSE / Streamable HTTP 三种传输）、凭证管理（加密存储，OAuth 流程）、工具自动发现与 Tool Registry 同步、工具调用审计、**安全边界**：MCP 工具默认不信任，需管理员审核启用；执行隔离（超时/并发/参数校验）。

### 3.7 横切能力（容易被漏掉但决定产品死活）

- **权限与多租户**：租户 → 工作区 → 用户三级；资源（知识库/专家/技能）按工作区隔离 + 共享机制。
- **可观测性**：每次对话/Agent 运行记录 trace（LangSmith 或自建 OpenTelemetry：提示词、检索命中、工具调用、耗时、Token 费用）。
- **评测**：RAG 评测集（query→期望出处）、问答质量回归测试，改提示词/换模型前先跑评测。
- **API 开放**：核心能力全部有 REST/SDK，产品自己也是自己 API 的第一个消费者。

## 4. 系统架构

```
┌─ 前端 (React 18 + TypeScript + Tailwind, Vite) ────────┐
│  对话 UI · 知识库管理 · 专家/技能工作台 · 管理后台      │
└──────────────────────┬─────────────────────────────────┘
                       │ REST + SSE
┌──────────────────────▼─────────────────────────────────┐
│                API 网关 (FastAPI)                       │
│   认证/鉴权 · 限流 · 审计 · 会话路由                    │
├──────────────┬──────────────────┬──────────────────────┤
│  会话与问答服务 │  Agent 编排服务   │   管理域服务          │
│  (流式/引用)   │  (LangGraph)     │  (KB/技能/专家/MCP)   │
├──────────────┴──────────────────┴──────────────────────┤
│                    共享能力层                            │
│  RAG 检索引擎 · Tool Registry · Memory · Prompt 管理    │
├─────────────────────────────────────────────────────────┤
│  模型接入层（统一 OpenAI 兼容接口）                      │
│  llama.cpp 本地 LLM · 嵌入模型 · Reranker · 云端模型     │
└──────┬──────────┬──────────┬──────────┬────────────────┘
       │          │          │          │
   Postgres      Milvus     Redis      MinIO
  (元数据)     (向量检索)   (缓存/      (原始文件)
                            队列)
```

要点：

1. **异步任务分离**：文档摄取、批量嵌入走任务队列（Celery/Arq），不阻塞 API。你已有的批量嵌入流程直接归入此管道。
2. **模型接入层统一抽象**：本地 llama.cpp（Qwen3.6-27B）与云端模型走同一接口，按"专家偏好 + 用户选择 + 降级策略"路由。嵌入与 LLM 分开配置。
3. **RAG 引擎独立成服务**：检索是被会话、智能体、检索测试台三方共用的能力，必须收敛到一处。

## 5. 前端设计（React + TypeScript + Tailwind CSS）

### 5.1 技术栈选型

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | React 18 + TypeScript + Vite | 纯应用型产品无 SEO 需求，Vite 启动快、构建产物干净；不用 Next.js 省掉一层复杂度 |
| 样式 | Tailwind CSS | 原子类直接对应设计 token，主题切换（亮/暗）用 CSS variables 驱动 |
| 组件底座 | shadcn/ui（Radix primitives） | 无头组件 + 代码归自己所有，样式全靠 Tailwind 定制，契合"大气自研风" |
| 数据层 | TanStack Query（服务端状态）+ Zustand（本地 UI 状态） | 会话流、知识库列表等缓存失效策略清晰 |
| 路由 | React Router v7 | SPA 多工作区路由 |
| 富文本渲染 | react-markdown + Shiki 代码高亮 | 对话流式 Markdown 渲染 |
| 表单 | react-hook-form + zod | 专家/技能配置表单，schema 与后端 Pydantic 对齐 |

### 5.2 整体布局（信息架构）

主框架：**左侧固定导航栏（240px）+ 顶部工作区栏 + 右侧内容区**。

```
┌────────┬──────────────────────────────────────────┐
│  Logo  │  工作区切换 · 全局搜索 · 主题切换 · 用户   │
├────────┼──────────────────────────────────────────┤
│ 对话    │                                          │
│ 知识库  │              内容区                       │
│ 专家    │   （对话页 = 会话列表 + 聊天流 + 引用侧栏）│
│ 技能    │                                          │
│ 智能体  │                                          │
│ MCP    │                                          │
│ ────── │                                          │
│ 管理    │                                          │
└────────┴──────────────────────────────────────────┘
```

页面清单（路由规划）：

| 一级 | 页面 | 关键交互 |
|---|---|---|
| `/chat` | 对话工作台 | 三栏：会话列表 / 聊天流 / 引用溯源侧栏；专家切换器；流式渲染 + 思维步骤折叠 |
| `/kb` | 知识库列表 → 详情 | 详情含文档管理、摄取任务状态、**切片预览**、**检索测试台** |
| `/experts` | 专家工作台 | 分步编辑器：人设 → 技能勾选 → 知识库挂载 → 模型参数；右侧实时预览对话效果 |
| `/skills` | 技能中心 | 技能卡片流、导入导出、沙箱调试（试运行看工具调用轨迹） |
| `/agents` | 智能体配置 | 编排图预览、运行历史、Trace 查看器 |
| `/mcp` | MCP 管理 | Server 注册向导、工具发现清单、审核开关、凭证状态 |
| `/admin` | 系统管理 | 用户/权限、模型接入、观测面板、审计日志 |

### 5.3 视觉风格：「大气、自然得体」

气质锚点：Linear / Vercel / Notion 的克制感——**靠留白和字重做层级，不靠颜色和边框堆装饰**。

- **色彩**：中性灰为绝对主导（90%+ 界面），单一品牌色只用于主按钮、焦点态、进度；语义色（成功/警告/危险）仅在状态出现时出现。亮暗双主题，用 CSS variables + Tailwind `dark:` 实现，跟随系统可手动切换。
- **留白**：内容区最大宽度约束（聊天流 ~760px 居中），区块间距 24/32/48px 阶梯，宁可空不可挤。
- **字体**：系统字体栈（PingFang SC / HarmonyOS Sans / Segoe UI 回退）；正文字号 14px、行高 1.6+；标题靠字号+字重（500）区分，不用纯色块标题条。
- **形状与阴影**：圆角 8/12px 两档；层级用低透明度阴影 + 背景色深浅（`bg-surface` 三级）表达，弱化 1px 边框。
- **动效**：只做两处——流式输出的打字/淡入、面板展开收起（150–250ms ease-out）。禁止装饰性动画。
- **对话区**：气泡低饱和（用户消息品牌色 8% 底，AI 消息无底色）；引用卡片是核心组件——来源标题 + 命中段落 + 相似度，点击滑出原文定位。

### 5.4 Tailwind 设计 token 规划

```ts
// tailwind theme 扩展（示意）

  brand:   { DEFAULT: ..., fg: ..., muted: ... },   // 单一品牌色阶
  surface: { 1: ..., 2: ..., 3: ... },              // 页面/卡片/浮层三级底色
  line:    { subtle: ..., strong: ... },            // 边框两档
}

radius:   { DEFAULT: 8px, card: 12px }
shadow:   { card: 低透明度大范围, float: 浮层用 }
```

### 5.5 核心业务组件（在基础组件之上）

- `<ChatStream>`：SSE 流式渲染、Markdown、思维/工具步骤折叠面板、消息分支（重新生成）
- `<CitationCard>` / `<CitationDrawer>`：引用卡片与溯源侧栏
- `<ExpertPicker>` / `<ExpertEditor>`：专家切换与分步编辑器

- `<SkillSandbox>`：技能试运行沙箱

## 6. 核心数据模型

```
Tenant ─< Workspace ─< User

KnowledgeBase (ACL) ─< Document ─< Chunk
                          │ (hash 去重、版本)

Conversation ─< Message ─< TraceStep (检索/工具/思维记录)
     │
     └─ AgentRun (LangGraph 状态快照)

Expert ─< ExpertSkill >─ Skill ─< SkillTool >─ Tool
   │                                    ↑
   └─ ExpertKB >─ KnowledgeBase         │
                              McpServer ─< McpTool → 同步进 Tool
```

Tool 表是关键枢纽：`source` 字段区分 builtin / mcp / custom，技能与智能体只引用 Tool ID。

## 7. LangChain 技术选型映射

| 需求 | 选型 | 说明 |
|---|---|---|
| 文档加载/切分 | langchain community loaders + TextSplitter | 切片策略可配 |
| 嵌入 | HuggingFace/自定义 Embeddings 类对接 llama.cpp server | 你已有 Qwen3-Embedding-8B |
| 检索 | SelfQueryRetriever / EnsembleRetriever（向量+BM25 混合） | 加 Reranker 后置 |
| 向量库 | **Milvus**（langchain-milvus） | 独立向量检索服务；开发期用 milvus-lite，生产 Standalone（Docker，建议跑在 WSL2——Milvus 不支持 Windows 原生部署） |
| Agent 编排 | **LangGraph** | 核心选择，支持循环/中断/检查点 |
| 模型接入 | ChatOpenAI 指向 llama.cpp server 的 OpenAI 兼容端点 | 云端模型同接口 |
| 观测 | LangSmith（快速起步）→ 自建 OTel trace（长期） | |
| 结构化输出 | Pydantic + with_structured_output | 专家配置校验、工具参数 |

## 8. 迭代路线（建议四个里程碑）

**M0 —— RAG 问答闭环（最优先）**
模型接入统一层 + 知识库摄取管道 + 混合检索 + 流式问答 + 引用溯源。
前端同步起步：Vite + React + Tailwind 工程初始化、主布局（侧导航+内容区）、`/chat` 对话页三栏骨架、亮暗主题 token。
验收：上传一份 PDF，问答能给出带出处的正确回答。

**M1 —— 智能体**
Tool Registry + 内置工具（搜索/计算器/代码执行）+ LangGraph ReAct 循环 + 运行过程可视化 + 会话记忆。
验收：Agent 能多步调用工具完成一个任务且过程可见。

**M2 —— 技能 + 专家体系**
技能包格式与 CRUD、专家结构化配置、专家-技能-知识库组装、专家发布流。
验收：不写代码创建一个挂了知识库和技能的专家并上线对话。

**M3 —— MCP + 平台化**
MCP Server 接入与审核、凭证管理、多租户权限、可观测后台、评测集、开放 API。
验收：接入一个第三方 MCP Server，其工具可被技能引用并通过审计。

每个里程碑都可独立交付使用，M0 就能支撑内部试用。

## 9. 关键风险与对策

| 风险 | 对策 |
|---|---|
| RAG 效果不达预期 | 检索测试台 + 评测集先行，调参有依据；切片策略按文档类型分库配置 |
| 本地模型工具调用能力弱（Qwen3.6-27B Q4 量化后 function calling 不稳定） | M1 优先做工具格式校验 + 失败重试；关键路径可配云端模型 |
| MCP 安全（任意代码/外呼） | 工具审核制 + 执行隔离 + 全量审计日志 |
| 概念过多用户看不懂 | 前端默认给模板：预置 3-5 个专家模板，用户改了就能用 |
| 技能包生态无人贡献 | 先把导入导出和调试沙箱做好，让内部团队先用起来 |
