# UI 走查与 UX 评估报告（2026-11-10）

**方法**：playwright + 系统 Chrome 对全站 12 个路由 × 亮/暗两主题截图（1440×900），并脚本采集客观指标：WCAG 文本对比度（含背景叠加计算）、<12px 字号、<24px 点击目标、水平溢出、无标签图标按钮；另补 880px 窄窗口响应式截图。共 24 张截图 + 全量指标数据。

**范围**：login / chat / agents / kb / browser / experts / models / mcp / eval / platform / ops / admin。

---

## 总体结论

设计系统本身是健康的：token 化配色、两页共用的输入器、统一的卡片语言、空态引导完整、窄窗口无一处横向溢出。**问题集中在三类**：① 品牌绿在亮色主题下被直接当文字色用（对比度硬伤）；③ 辅助文字色 `tertiary` 全站低于 AA 线；③ 若干小点击目标和危险操作无视觉区分。修的都是 token 和局部类名，不需要动布局。

---

## P0 —— 可读性硬伤与安全隐患

### 1. 亮色主题下品牌绿当文字色，对比度不达标（全站高频）

实测：`text-brand`(#00c29a) on 白 ≈ **2.3:1**，on 品牌绿软底 ≈ **1.83:1**（AA 正文要求 4.5）。暗色下同 token 是 8.6:1 达标——所以暗色用户（你）没感知，亮色用户读不清。

| 位置 | 代码 |
|---|---|
| 侧栏导航选中态 | `AppLayout.tsx:66` `bg-brand-soft font-medium text-brand`；`:82` `isActive ? "text-brand"` |
| 用户菜单头像字 | `UserMenu.tsx:60` `bg-brand-soft text-brand` |
| 工作区切换选中项 | `WorkspaceSwitcher.tsx:125` `bg-brand-soft text-brand` |
| 可见范围徽章（工作区） | `visibility.tsx:26` `bg-brand-soft text-brand` |
| 联网按钮/专家选中 chips 等零散处 | chat/agents 页若干 `text-brand` |

**修法**：亮色文字一律用 `--brand-deep`(#087866，白底 5.4:1 达标)，暗色保持 `text-brand`。项目里已有现成模式：`TaskSidebar.tsx:150` 用的就是 `text-brand-deep dark:text-brand`——把上面几处统一成这个模式即可。

### 2. 登录页明文展示初始账号 + 一键填入，无环境门禁

`LoginPage.tsx:413-430`：「初始账号 admin / admin123」+「一键填入」按钮，`grep` 确认**没有** `import.meta.env.DEV` 保护。开发便利可以留，但生产构建必须隐藏——这是安全项。

### 3. 危险操作与小点击目标（WCAG 2.5.8 最低 24×24）

- **admin 成员表**：改密码 / 禁用 / 删除是裸文字按钮，实测 **36×16 / 24×16**，删除 hover 才变红、常态与普通操作无区分（`MembersCard.tsx:229-249`）。上一轮已给知识库删除做 hover 化 + confirm，这里没同步。
- 「清空指标」（admin 右上灰字）同样是危险操作无强调。
- 其余实测过小目标：kb「从服务器目录导入」161×17、kb 检索模式切换 42×22、platform「导出 CSV」67×22、ops「去模型页」46×15、browser「刷新文件列表」图标 **14×14**、agents 工具栏图标按钮 21×21（5 个）。

## P1 —— 全站性打磨

### 4. `tertiary` 辅助文字全站低于 AA 线（每页 4~13 处）

亮色 45% 黑 on 页面底 = **2.86:1**；暗色 45% 白 = **3.79~3.89:1**。涉及：侧栏分组标题、版本号、文档元信息（"66 个切片 · zip · 时间"）、表单说明、表格次要列。
**修法**：`--text-tertiary` 透明度 45% → 60% 左右（亮 ≈4.6:1、暗 ≈5:1 达标）。**一行 token 改动，全站受益**。

### 5. 11px 中文发虚

侧栏分组标题 11px、版本号 11.5px、kb 文档元信息 11px、agents 任务列表元信息 11px。中文在 11px 下笔画粘连，建议全站下限提到 12px（元信息 12px + tertiary 60% 后依然有清晰的层级差）。

### 6. 运营页「按天趋势」整块实心品牌绿

数据只有一天时，趋势图被绿色填满成一个巨大的实心色块（截图 ops-dark），大面积品牌绿刺眼——正是上一轮改版要消除的方向。需要给面积图加渐隐（向下透明渐变）或描边式呈现。

### 7. 「当前默认」徽章绿字叠绿底

kb-dark 实测出现 **1:1 对比**的「工作区」徽章（文字 rgb(47,214,176) 与背景同色，完全不可读），models 页「当前默认」Badge 同款。需查 badge 实际渲染的背景（疑似实心 brand 底配了 text-brand）。

### 8. 窄窗口（<1024px）知识库页三栏挤压

880px 时侧栏 236px + 知识库列表 ~280px，文档区只剩 ~350px；右上按钮组「共享给成员/对外分享/可见范围/工作区」挤压，「工作区」按钮贴边。建议 <1024px 时折叠知识库列表为下拉。其余页面窄窗口表现正常（无溢出、无裁切）。

## P2 —— 细节与一致性

9. **页面标题基线不统一**：platform 页标题左缘对齐的是卡片内 padding（差卡片边界 24px），其余页对齐卡片边界，应统一。
10. **kb 页右上四个操作按钮权重相同**（共享给成员/对外分享/可见范围/工作区全是 outline），没有主操作；「可见范围」其实是状态展示混在按钮里。
11. **空态缺视觉锚点**：experts/eval 空态纯一行字，可加图标 + 次要说明；chat/agents 空态已经做得好（建议 chips + 模板），可作为标准。
12. **admin 长期记忆行的「对话反馈 👍0 👎0」**：emoji + 数字挤在 12px 里，可读性差。
13. **platform 审计表密钥列**全部显示 `useradmin`，信息量为零——建议显示密钥名称/前 6 位摘要。

## 对比度速查表（实测）

| 组合 | 对比度 | AA(4.5) |
|---|---|---|
| 亮 text-brand on 白 | 2.3:1 | ❌ |
| 亮 text-brand on brand-soft | 1.83:1 | ❌ |
| 亮 text-brand-deep on 白 | 5.4:1 | ✅ |
| 暗 text-brand on surface-1 | 8.6:1 | ✅ |
| 亮 tertiary(45%黑) on page | 2.86:1 | ❌ |
| 暗 tertiary(45%白) on surface | 3.79:1 | ❌ |
| 暗 primary 按钮深字 on 渐变 | ~8.7:1 | ✅ |
| 亮 primary 按钮白字 on 渐变 | ~2.5:1 | ❌* |

\* 亮色主按钮白字不足 AA，但绿底白字是行业常态（微信/支付宝同款），改深字会损失品牌感；可考虑只把渐变加深一档（中值 ~3:1 达大字 AA），列为讨论项。

## 建议修复顺序

1. **第 1 批（半天）**：P0-1 文字色模式统一（~6 处类名）+ P1-4 tertiary token 一行改动 + P0-2 登录页 DEV 门禁。三项都是小改动，可读性提升最大。
2. **第 2 批（半天）**：P0-3 危险操作统一为 danger 文字按钮（admin 表、清空指标、导出 CSV 等加 padding 至 ≥24px）；P1-6 图表渐隐；P1-7 徽章底色。
3. **第 3 批（按需）**：P1-5 字号下限、P1-8 kb 窄窗口折叠、P2 全部。
