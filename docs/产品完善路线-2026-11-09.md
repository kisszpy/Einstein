## 一、结论

**评级：小团队可用（单机单副本），未达生产可用。**

不是能力不够——后端 122 个端点、6 段用户旅程都有实现，51 项 pytest + 30 余个验收脚本在跑。
问题是三类：

1. **有开关但没通电**：限流、日请求配额、审批、MCP 加密，代码都在，实际不生效或默认关闭；
2. **有接口但没界面**：知识库管理六个接口前端零调用，用户能上传不能管；
3. **有实现但不闭环**：断连重传只做了后端、赞踩只采集不消费、重排只写代码不开默认。

一句话：**先把已有能力的插头插上，再谈新功能。**

## 二、立刻要修的六件（合计约 3 天，收益最大）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **用户级限流整体失效**：限流中间件先于鉴权执行，读不到 `request.state.user`，直接放行 | `main.py:150` 注册晚于 `main.py:86`；Starlette 后注册者在外层；`main.py:179-181` `user is None → call_next` | 对话 60/min、智能体 30/min、检索 120/min 全部不生效；只有登录撞库防护和 `/v1` 的 Key 限流是真的 |
| 2 | **日请求配额从未累加**：`quota_incr` 只有 `kind="tokens"` 一个调用点 | `ratelimit.py:115` 定义，唯一调用 `ratelimit.py:150`；`main.py:142` 只 `quota_check("requests")` | 配 `APP_QUOTA_DAILY_REQUESTS` 等于没配，`used` 永远 0 |
| 3 | **知识库管理无界面**：切片列表/编辑、删单篇、单篇重建、版本列表/回滚六个接口前端零调用 | 后端 `routes/kb.py:469/493/512/528/543/563`；前端 `KbPage.tsx:318-333` 只渲染名称+切片数；`web/src` 搜 `chunks/versions/rollback/reindex` 在 KB 域零命中 | 传错文件、切坏表格没有任何补救路径，只能删整库重传（重付全部嵌入成本） |
| 4 | **共享能力不成立**：库/专家/技能都按 `owner_id` 过滤；`visibility` 有三档定义但创建时硬编码 `workspace`，且无 PATCH 入口 | `repositories/kb.py:191`、`:420`（list 按 owner）；`:442`（硬编码）；`experts.py:63-66`、`skills.py:123` 同构 | 同事登录看不到你建的库与专家，"团队版"叙事不成立 |
| 5 | **刷新即失联**：后端已实现断连转后台 + `GET /agent/runs/{id}/stream`，前端从未调用 | 后端 `routes/agent.py:397`；前端 `AgentsPage.tsx` 只用 `/run`、`/runs`、`/approve`、`DELETE` | 在 2-3 分钟的长任务上，用户不敢刷新；"真流式 + 断连转后台"的投入卡在最后一米 |
| 6 | **删除不级联**：删文档/删库不清理 `document_versions`，表无外键 | `routes/kb.py:445-450`、`:524-528`；`schema.py:162` | 已删内容正文永久留存；"删了资料"在合规上不成立；表无界增长 |

> 另有两处安全问题（半天可修）：
> **MCP 凭证加密不是 Fernet**，是自写 SHA256 计数器流 XOR、无 MAC（`services/mcp.py:82-100`），且 `secret_key` 默认为 `einstein-local-secret-change-me` 无启动校验（`config.py:91`）→ 拿到配置文件即可还原全部凭证。
> **Pro 沙箱降级会变永久**：非 root 写失败后以 root 重试，root 生成的文件属主是 root，此后每次都会降级（`agent_deep_pro.py:242-253`）。

## 三、功能缺口（按用户旅程，只列 P0/P1）

### ① 把资料放进来
- P1 **源同步缺失**：URL 入库后不再抓取，文档不会过期提醒。制度改了三个月，AI 还按旧版答——这是知识库腐烂的头号原因。
- P1 **扫描件进不来**：图片不在白名单，OCR 只有 Protocol 接口（`parsers.py:41`）。合同/档案类客户直接被挡在门外。
- P2 批量导入失败后无一键重试（失败明细已有，`BatchImport.tsx:412`）。

### ② 找到对的片段
- P0 **重排默认 `none`**（`config.py:43`），代码按"已重排"语义写。这是"明明库里有，它却答另一段"的第一归因。
- P1 **重排分不透出**：检索测试台给了 vec/bm25/rrf，缺 `rerank_score`，无法判断该不该开。
- P2 门限是全局一个数，不能按库/按专家调；未命中只回一句"未命中"，不给最接近的候选与差分。

### ③ 问出可信答案
- P0 **无负例评测**：`EvalItemIn` 只有 `query/expected_doc/expected_contains`，表达不了"库里没有答案，应回答不知道"。
- P0 **无重新生成**：`chat.py` 只有一个 `POST ""`，答得不好只能重新打字。
- P0 **赞踩只采集不消费**：`/api/feedback` 落 `message_feedback` 表（上限 5000），但不采集原因、不进评测集、不影响提示词——表在变大，系统行为从未因它改变。
- P1 无编辑后重发、无分支；无会话级温度/引用上限。

### ④ 让智能体替我做长任务
- P0 **审批默认关闭**：`agent_approval_tools` 默认空（`config.py:62`），能力完整（interrupt + checkpointer + TTL，验收 15/15）但用户不知道它存在。
- P0 **无 trace**：`GET /agent/runs` 只回 steps 数与答案；`run_registry` 事件在进程内且截断。跑了 5 分钟，钱花哪了、哪步错了，答不上来。
- P1 无任务模板（"每周竞品简报"这类固定流程），每次都要重新描述。

### ⑤ 团队一起用
- P1 无知识库级权限（不能指定"这个库只给财务组"）。
- P1 无成员用量视图（看不到谁问了多少、花了多少）。

### ⑥ 长期运维与算账
- P0 **无成本看板**：`record_llm` 记了 model+tokens，但没有 user/workspace 维度、没有单价、没有金额。"这个月谁花了多少"答不上来——自托管交付的必答题。
- P1 无告警（配额触顶、错误率、模型不可用、未命中率都无通知）。
- P1 备份/恢复脚本齐全（`backup.py` 含 `restore` 子命令，三后端支持），但无定时、无保留策略、无恢复演练。
- P2 无用量趋势与容量基线（"照这个速度磁盘还能撑多久"）。

## 四、撑不住规模的结构问题（要做大必须处理）

| 问题 | 到什么量级会坏 | 结论 |
|---|---|---|
| **运行态在进程内**：`run_registry._RUNS` 模块级 dict（`run_registry.py:26`），重连只查本进程 | 第 2 个副本就 404 | 事件日志必须外置（`run_events` 表或 Redis Stream），否则永远单副本 |
| **检索全库进内存**：hybrid 每查询 `list_chunks(kb)` 再建 BM25（`rag.py:393/415`） | 单库 >3 万片 p95 破 1s；>20 万 OOM | BM25 倒排按"库+切片版本"缓存，中期词法下沉 Milvus 全文或 PG `tsvector` |
| **队列不是真的"至少一次"**：Redis 领取 hset 与 zadd 非原子（`redis_queue.py:140-146`）；`renew` 不校验 worker；失败立即重排无退避 | 任务 >5 分钟或并发 worker ≥2 时重复执行；崩溃窗口任务永久卡 running | pipeline/Lua 原子化 + worker 校验 + 指数退避 + 幂等键 |
| **指标是单文件 JSON**：每请求全量 `write_text`（`metrics.py:37-40`），只留 2000 条 | 多进程互相覆盖，轮转后无法算月账 | 落 `run_traces` 表（按 run 维度），见架构报告 §4 |
| **文件系统是隐式共享状态**：projects/uploads/staging/metrics/checkpoints 全在 `appdata` 卷 | backend 与 worker 不同机即"上传文件已不存在" | 元数据进 DB、正文进对象存储；projects 保留本地 |

## 五、三个版本的切分

### v0.7.0 —— 把插头插上（不新增能力，只补闭环）
1. 六件立刻修（§二）+ MCP 加密换 Fernet + `secret_key` 启动校验
2. 知识库管理界面（切片/版本/重建/删除/失败重试）
3. 共享模型：库/专家/技能「私有 / 工作区」+ 修正 list 过滤 + UI 开关
4. 检索可信：重排默认开 + 开/关基线数据 + 负例集 + 差评一键进评测集
5. 可信对话：重新生成 + 编辑后重发 + 赞踩采集原因
6. 运行可见：轻量 trace（run_traces 表）+ 前端接重连接口 + 审批默认开

**验收一句话**：刷新页面任务还在跑；传错文件能单独删；同事能看到我共享的库；差评能变成评测用例；失败运行能看到第几步、哪个工具、多少 token。

### v0.8.0 —— 团队与运营
模型注册表 + 按专家选模型；成本看板（模型×成员×工作区×天）；告警；文档源同步；知识库级权限 + 成员用量；任务模板。

### v1.0.0 —— 可交付
OCR + 图片摄取；备份运营化（定时/保留/演练/恢复自检）；发布与嵌入（免登录链接/iframe）；会话导出；容量基线与迁移手册。

## 六、不建议做

| 项 | 为什么不做 |
|---|---|
| 可视化工作流画布 | 与"智能体自主规划"定位正面冲突，等于换产品；用任务模板覆盖 80% 场景 |
| 自研推理网关（vLLM/GPU 池化） | 客户自带 OpenAI 兼容端点，做调度等于变基础设施公司 |
| 文档级 ACL | 会让召回、缓存、评测全部复杂化；先把库级可见范围做好 |
| 会话社交化（点赞排行/评论） | 企业知识库是"查完就走"的工具，收益低、审核成本高 |
