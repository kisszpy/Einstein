## 三、缺陷清单

### BUG-01【P0】打开历史会话必定 500，且响应体是完整堆栈

- **现象**：`GET /api/conversations/{id}` 返回 500，响应正文为 11.9KB 的 Python traceback；前端点击左侧任意历史会话**毫无反应、无任何提示**。
- **复现**：登录 → 对话页 → 点击任一条历史会话。
- **根因**：`HistoryStore.load()` 里 `Conversation(**v)` 只还原了外层 dataclass，`messages` 仍是 `list[dict]`；路由里 `m.role` 触发 `AttributeError: 'dict' object has no attribute 'role'`。列表接口只用 `len()` 所以正常，只有详情接口会炸。
- **影响**：所有历史会话不可读（11 条会话 100% 失败），且堆栈泄漏服务器路径。
- **修复**：`server/app/services/history.py` 加载时把每条消息转成 `StoredMessage`。前端 `use-chat-stream.ts` 在打开失败时给出明确提示，不再静默返回。
- **状态**：已修复，回归通过（会话详情 200，UI 点击可正常渲染历史消息）。

### BUG-02【P0】未捕获异常把堆栈直接返回给客户端

- **现象**：任意未捕获异常（如 BUG-01、BUG-03）都返回 `+ Exception Group Traceback ... File "C:\...\site-packages\..."`。
- **根因**：`FastAPI(debug=settings.debug)`，而 `.env` 里 `debug` 默认 `True`；Starlette 在 debug 模式会忽略自定义异常处理器，直接输出堆栈。
- **影响**：任何登录用户（含只读成员）可获取服务器绝对路径、依赖库版本、内部函数名，属于信息泄漏；同时破坏前端 `res.json()` 解析，引发二次故障（见 BUG-04）。
- **修复**：`server/app/main.py` 固定 `debug=False`，新增全局 `Exception` 处理器，统一返回 `{"detail": "服务器内部错误，请稍后重试或联系管理员"}`，完整 traceback 由 `app.errors` logger 落到服务端日志。
- **状态**：已修复，回归通过（异常场景返回 500 JSON，无堆栈）。

### BUG-03【P1】嵌入服务不可用时，检索返回 500，与入库行为不一致

- **现象**：入库失败返回 503 +「嵌入端点不可用…已禁止降级」，而检索（`/api/kb/search`、`/v1/search`）返回 500 + 堆栈。
- **根因**：`kb.py` / `openapi.py` 的检索分支没有捕获 `embed_texts` 抛出的 `RuntimeError`；入库分支捕获了。
- **影响**：检索测试台、开放检索接口在嵌入服务抖动时不可用，且错误不可读。
- **修复**：两个路由统一 `except RuntimeError → HTTPException(503, str(exc))`。
- **状态**：已修复。嵌入服务恢复后复测：`/v1/search` 命中 2 条（score 0.0328），`/api/kb/search` 正常。

### BUG-04【P1】知识库检索失败后按钮卡在 loading，且无任何错误提示

- **现象**：检索台点「检索」后若后端异常，按钮长期处于 disabled，页面无提示，用户以为卡死。
- **根因**：`KbPage.runSearch` 直接 `setHits(await res.json())`，响应非 JSON 时抛异常，`setBusy(false)` 永远执行不到；页面也没有 error 状态。
- **影响**：检索/入库/新建库共用 `busy`，一处失败会连带其它按钮不可用。
- **修复**：新增 `readError()` 统一取错误信息；`createKb/addDoc/uploadFile/runSearch` 全部改为 `try/catch/finally`，失败时在详情区顶部展示可关闭的红色提示条。
- **状态**：已修复，实测 503 场景 5 秒内按钮复位并显示可读原因。

### BUG-05【P1】历史会话点击静默失败

- **现象**：`loadConversation` 在 `!res.ok` 时直接 `return`，用户没有任何反馈。
- **修复**：区分 404 与其它错误，`window.alert` 明确提示。
- **状态**：已修复（与 BUG-01 同批）。

### BUG-06【P2 · 未修】非法项目名被静默改写

- **现象**：`POST /api/projects {"name":"../escape"}` 返回 200，实际创建的是 `escape`。
- **分析**：`slugify()` 已消除穿越风险（不会写出项目根目录），属于安全可控，但**静默改名**让用户拿到与输入不符的项目名（中文名也会被 slug 化）。
- **建议**：接口返回中带上 `requested_name` 与 `project`，前端在「名称被规范化」时提示一次；或对仅含非法字符的输入直接 400。

### BUG-07【P2】MCP 服务器启动失败时错误不可读

- **现象**：`command` 不存在时刷新/调用返回 `502 ExceptionGroup: unhandled errors in a TaskGroup (1 sub-exception)`。
- **影响**：用户无法判断是命令路径错、依赖缺失还是传输配置错。
- **建议**：在 `mcp.call_tool/refresh_server` 捕获启动异常，附上 `command + args` 与子进程 stderr 尾部（限 500 字）。

### BUG-08【P3】对话页没有侧栏折叠

- 智能体页有「收起任务栏」，对话页缺失，窄屏下会话列表占宽且无法隐藏。
- **建议**：复用智能体页的折叠控件；键盘快捷键（如 `Ctrl+B`）统一。

### BUG-09【P3】对话首字延迟偏高

- 实测首字 2.4–3.6s、整句 3.7–4.3s（上游 DeepSeek API + 网络）。后端确为真流式（`stream=True`），非产品缺陷。
- **建议**：前端在等待期间展示「思考中/检索中」占位；考虑边缘节点或本地模型兜底。

## 六、风险与改进建议

### P0 级（上线前必须处理）

1. **错误响应统一**：已加全局处理器，但建议补 `RequestValidationError` 的中文文案（当前 422 直接透传 pydantic 结构，用户看不懂）。
2. **嵌入服务强依赖**：知识库、评测、检索全部依赖 `8180`。建议
   - 启动时探测嵌入端点，健康页显示「检索不可用」而非等到用户操作才 503；
   - `retrieval_mode` 支持 `lexical` 自动兜底（代码已支持模式切换，缺自动降级）；
   - 生产环境把嵌入服务纳入 systemd/容器编排的健康检查与重启策略。

### P1 级（近期迭代）

3. **存储层仍是单文件 JSON**（`data/history_store.json`、`data/kb_store.json`）：多进程部署会互相覆盖，写入时无原子替换（`.tmp` + rename），进程崩溃可能丢数据。建议迁 PostgreSQL + Redis（设计文档里已预留 DSN 配置），先做「写前备份 + 原子重命名」止血。
4. **无速率限制**：`/api/auth/login` 可无限重试（仅记审计），`/v1/*` 无 QPS 配额。建议对登录按 IP+账号做滑动窗口限流，对 API Key 做每分钟配额与用量统计。
5. **失败反馈规范**：本轮修了知识库与对话，建议全站统一 Toast/内联错误组件，禁止 `catch {}` 静默吞错（`KbPage` 里几处 `fetch` 仍未包错误处理，如删除文档）。

### P2 级（体验与质量）

6. **测试入 CI**：`full_sweep.py` + `ui-sweep.cjs` 目前手动跑。建议 PR 流水线跑 `--skip-live` 版本（约 40 s），每日定时跑 live 版。
7. **功能缺口**：会话重命名/搜索、知识库单文档删除、任务并发上限与队列可见性、评测集多轮对比视图。
8. **可观测性**：已有请求/模型指标，缺「错误率 + 5xx 告警」与前端错误上报；建议接入 Sentry 或自建 `/api/obs/errors`。

### P3 级（打磨）

9. 对话页侧栏折叠、统一快捷键；长会话滚动位置记忆；PPT 编辑器撤销/重做。
